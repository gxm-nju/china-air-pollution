# 中国城市重污染日从哪里来？

大数据系统中期项目。把地面站、卫星、气象、火点和地图放到同一时间与空间尺度上，检验火点下风向的浓度变化、卫星估算地面 NO₂ 的表现，以及长三角重污染过程的气象特征。全国日档用来识别事件，长三角 41 城用于跨源分析。

## 三个问题的实测结果

| 问题 | 样本和检验 | 结果与适用范围 |
|---|---|---|
| 火点发生后，PM₂.₅ 的变化随风向而异吗？ | 75 天，811 个满足五个滞后都有上下风观测的网格小时。比较相对于事前 24 小时的浓度增幅，按锚定日自举 | 第 12 小时下风减上风平均 **+9.61 µg/m³**，95% 区间 [2.08, 18.15]。限定至少两个火点小格中心命中已绘制农田后只剩 12 个锚点，区间跨零。无法据此判定秸秆燃烧的因果贡献。 |
| 气象能否改善卫星对地面 NO₂ 的预测？ | 2023 年第一季度，1,946 个城市日，81 个日期、37 个卫星格。比较岭回归的空间与时间留出误差 | 加入气象后，空间留出 MAE 从 **6.20 降至 5.52 µg/m³**，留出 3 月时从 **5.81 升至 6.74 µg/m³**。 |
| 长三角出现多少段重污染？春节如何？ | 至少 20 个有效小时算合格城市日，PM₂.₅ 日均严格超过 150 µg/m³，同城相邻日合并。缺测单独标识 | 5,410 个合格城市日里有 **29 个超阈值日、27 段过程**。2023 春节假期有 3 个超阈值城市日，2024、2025 春节缺站点日档，无法做三年同口径比较。 |

## 离线复算

在包含 Python 3.12 的 macOS 或 Linux 环境中，先在终端运行以下命令。首次安装依赖需要联网。核心分析的数据均随 Git 仓库提供。

```bash
git clone https://github.com/gxm-nju/china-air-pollution.git
cd china-air-pollution
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python reproduce.py
python visualization/redraw.py
```

输出在 `reproduced/`。入口先校验发布清单，随后从 2023 年正月初一的站点读数重建 984 个城市小时，并逐项比对九个浓度、站数和气象字段。火点检验从发布的上下风对照表重算；卫星检验从 90 个区域日数组重建格点时刻并训练模型；连续污染过程从全国城市日表重新切分。五张图单独写入 `reproduced/figures/`。绘图环境需有支持中文的字体，如 Noto Sans CJK SC。PNG 成品可直接查看。

## 覆盖和课程验收

主研究期为 2023—2025 年，地面实有 **134 / 1,096 天**，涉及全国 1,662 个有分析观测的站号。火点覆盖 2019—2025 年，气象四要素覆盖 41 个代表点三年，边界层高度有连续缺测。卫星主分析覆盖 2023 年第一季度；2024 年 10 月 1 日的一轨 L2 独立核验。地图快照晚于研究期。

| 作业指标 | 实测情况 |
|---|---|
| 至少 4 个独立来源、3 类数据，至少三个跨源问题 | 五个主来源，包含站点表、栅格、事件点与矢量地图。报告和独立关联图说明每个问题为何需要多个来源。 |
| 至少 5 张可视化并覆盖 3 个视角 | 月覆盖、火点滞后差、卫星分组散点、秋季火点分布和南京候选城市网络，分别对应时序、对比、空间及关系视角。 |
| 有效原始数据原则上 ≥2 GB，每个主要来源原则上 ≥200 MB，单一来源原则上 ≤80% | 按文件哈希去重后的原始输入共 2,799,760,907 字节，仍含重叠地图和研究区之外的内容。目前能单独核实用途的保守子集共 **79,249,804 字节**。两者分别是原始输入和加工后落盘体量，均不足以证明全部容量指标达标。计划书估算不能代替实测。 |
| 抽样和成员说明 | 已完成 200 个站号和 200 个火点格的计算核验，保存了区划证据和读图页。逐条人工读图、成员分工及个人反思待组员完成。 |
